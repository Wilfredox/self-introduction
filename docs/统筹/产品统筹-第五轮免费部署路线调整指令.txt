产品统筹 - 第五轮免费部署路线调整指令
更新时间：2026-04-26

一、当前新增约束

项目现在新增一个明确约束：
第一版部署必须优先按“免费方案”推进

这会直接影响部署路径选择。

因此从这一轮开始，之前默认的：
- 自购 Linux 服务器
- 自己托管 PostgreSQL
- 服务器本地磁盘上传

不再作为本轮默认路线。

二、第五轮冻结的免费路线（V1 免费技术上线版）

当前统一按下面这条免费路线推进：

1. 一个 Render Free Web Service
   - 用来同时承载：
     - 前端构建后的静态站点
     - 后端 Node API
   - 目标是保持同源访问，避免前后端跨域和 Cookie 问题

2. 一个 Supabase Free Project
   - 用来承载：
     - PostgreSQL 数据库
     - 文件存储（图片 / 项目 PDF / 简历）

3. 第一版先不购买域名
   - 先使用平台自带免费地址完成技术上线
   - 后续如果你愿意再买域名，再做绑定

当前冻结访问形态：
- 网站和后台：由同一个 Render 免费服务承载
- 数据库：Supabase Free Postgres
- 文件：Supabase Storage

三、为什么改成这条路线

原因不是“它最完美”，而是“它最接近零成本且最适合当前项目结构”。

核心原因：
1. 当前后台登录使用 Cookie Session
   - 如果前端和后端免费分散部署到不同域名，跨域 Cookie 会更麻烦
   - 把前端和后端一起放到同一个 Render Web Service，可直接保留同源登录方案

2. Render 免费数据库不适合当前这个网站长期持有内容
   - 免费 Postgres 有到期限制，不适合作为当前推荐主路线

3. Render 免费 Web Service 的本地磁盘不适合做长期上传存储
   - 免费实例会休眠，重启或重新部署后本地文件不可靠
   - 因此上传文件必须转到外部存储，而不是继续保存在服务本地目录

4. Supabase 免费项目同时提供：
   - Postgres
   - Storage
   - 这比“数据库一个平台、文件另一个平台”更适合当前低门槛免费路线

四、这条免费路线的代价

必须明确告诉所有人：
这是一条“免费可上线”的路线，不是“体验最优”的路线。

已知代价：
1. Render 免费 Web Service 会在空闲后休眠
   - 第一次打开网站可能要等一会儿

2. 第一版先不用自定义域名
   - 先用平台给的免费网址

3. 当前后端上传逻辑不能继续依赖本地 `uploads/`
   - 必须改成外部存储

4. 这条路线适合：
   - 免费演示
   - 技术上线
   - 先把站挂到网上
   不等于最终长期生产级方案

五、本轮明确不做的事

第五轮免费路线下，不做：
1. 不引入付费服务器
2. 不引入付费数据库
3. 不继续把本地磁盘上传当成正式免费方案
4. 不改登录机制
5. 不扩产品功能
6. 不新开设计方向

六、第五轮分工

[A] UI 设计

本轮角色：
免费上线后的视觉复核配合

本轮必须完成：
1. 不新增设计稿
2. 不参与平台选型
3. 仅保留一份“免费上线后仍需视觉复核”的页面清单
4. 不把自定义域名缺失视为当前阻塞项

UI 本轮输出要求：
在 `docs/交付/UI设计交付.txt` 中补一段：
- 第五轮免费部署路线下的 UI 结论
- 哪些页面即使挂在平台默认域名下也可接受
- 哪些问题只影响正式品牌感，不阻塞免费技术上线

[B] 前端开发

本轮角色：
适配“前后端同一个 Render Web Service”部署形态

本轮必须完成：
1. 确认前端生产构建产物可以由后端服务直接承载
2. 不再按“前端独立静态站点 + 单独后端域名”作为主路线
3. 保持前端 API 继续优先使用同源 `/api`
4. 补一份前端在 Render 同源部署下的说明
   至少写清楚：
   - 构建命令
   - 输出目录
   - 前端是否还依赖独立静态托管
   - 正式源码中是否还有任何单独部署假设

5. 配合后端确认：
   - 首页、作品详情、简历、后台登录、后台管理在同源部署下没有额外路径问题

前端本轮输出要求：
在 `docs/交付/前端交付.txt` 中补一段：
- 第五轮免费部署适配结果
- 前端对 Render 同源部署的要求
- 上线后最小前端 smoke check

[C] 后端开发

本轮角色：
免费部署主执行准备

本轮必须完成：
1. 将当前后端免费部署路线切换为：
   - Render Free Web Service 承载前端静态产物 + 后端 API
   - Supabase Free 承载 Postgres + Storage

2. 必须明确并推进以下事项：
   - 如何连接 Supabase Postgres
   - 如何把当前上传从本地 `uploads/` 改到 Supabase Storage
   - 如何由后端返回稳定可访问的文件 URL
   - 如何让 Render 上的同一个 Node 服务既提供 `/api`，也提供前端页面

3. 补齐 Render 免费部署说明
   至少写清楚：
   - Render 的启动命令
   - Render 所需环境变量
   - 如何部署单一 Web Service
   - 如何让服务同时承载前端静态页和后端 API

4. 补齐 Supabase 免费接入说明
   至少写清楚：
   - 需要哪些连接串
   - 需要哪些 Storage 配置
   - 当前 schema / migration 如何落到 Supabase Postgres

5. 在 `docs/交付/后端交付.txt` 中补一段：
   - 第五轮免费部署路线准备结果
   - 当前离 Render + Supabase 免费技术上线还差什么
   - 哪些是必须修改的代码，哪些只是部署动作

后端本轮通过标准：
1. 免费路线的真实阻塞已经列清楚
2. Render + Supabase 的执行路径已经说明白
3. 当前项目不再把本地 `uploads/` 当成免费正式路线

必须改成外部存储。

本轮推荐外部存储：
- Supabase Storage
