产品统筹 - 第十三轮 GitHub Pages 正式发布与首发验收指令
更新时间：2026-04-27

一、当前项目判断

当前主线已经是：

1. 纯静态作品集
2. 以 GitHub Pages 为默认发布目标
3. 不再依赖后台、数据库、上传或 CloudBase

并且当前已经满足：

1. 主线目录已清理
2. 公开页面结构已成立
3. GitHub Pages 工作流已存在
4. 内容入口已集中在：
   - `src/content/site.ts`
   - `src/content/projects.ts`

因此下一步不再是“继续开发”，而是：

第十三轮：GitHub Pages 正式发布与首发验收

二、本轮目标

本轮只做 4 件事：

1. 把最后一层公开文案微调落进代码
2. 恢复本地依赖并重新构建
3. 确认 GitHub Pages 发布配置可直接使用
4. 发布后做一轮首发 smoke check

本轮不新增功能，不回头恢复后台，不再讨论 CloudBase。

三、分工

1. UI 设计

职责：
- 只负责公开文案最后确认
- 不再改结构，不再补后台稿

本轮要看：
- 首页 eyebrow / 导语
- 作品列表页标题和说明
- 简历页说明文案

交付要求：
- 更新 `docs/交付/UI设计交付.txt`
- 只写清楚两件事：
  1. 哪几句文案建议改
  2. 当前版本是否已经能直接给招聘方看

2. 前端开发

职责：
- 本轮主负责人

本轮必须完成：
1. 安装依赖
   - `npm install`
2. 按已确认方向微调公开文案
3. 重新构建
   - `npm run build`
4. 检查 GitHub Pages 工作流：
   - `.github/workflows/deploy-pages.yml`
5. 确认默认分支监听是否正确
   - 目前默认是 `main`
6. 为发布后验收准备检查清单

交付要求：
- 更新 `docs/交付/前端交付.txt`
- 写清楚：
  1. 改了哪些公开文案
  2. build 是否通过
  3. GitHub Pages workflow 是否可直接用
  4. 发布后要怎么验

3. 后端 / 归档支持

职责：
- 本轮不再写后端代码
- 只做最后的归档说明和风险确认

本轮要做：
1. 检查当前 README / docs 是否还残留“后台仍会继续做”的误导性表述
2. 确认当前仓库公开主线只围绕静态站
3. 如果还有历史文档会干扰现在的 GitHub Pages 口径，列出来即可

交付要求：
- 更新 `docs/交付/后端交付.txt`
- 只写清楚：
  1. 当前没有新的后端阻塞
  2. 是否还有历史文档残留会影响理解

四、本轮禁止事项

1. 不新增页面
2. 不恢复后台
3. 不接数据库
4. 不再改部署平台
5. 不再把 `legacy` 类内容带回主线

五、本轮完成标准

满足下面 5 条，本轮就算通过：

1. 首页、作品列表页、简历页的说明式文案已微调
2. `npm install` 成功
3. `npm run build` 成功
4. GitHub Pages workflow 可直接用
5. 三方交付记录更新完成

六、发布后首发验收项

正式发布到 GitHub Pages 后，至少检查这些：

1. 首页能正常打开
2. 顶部姓名、简介、联系方式显示正常
3. 首页拼贴卡片可打开放大态
4. 作品列表页可打开
5. 作品详情页可打开
6. 简历页可打开
7. 404 路径跳转能回到 `#/`
8. GitHub Pages 默认地址可在他人设备访问

七、你可以直接发给三个人的话

项目进入第十三轮：GitHub Pages 正式发布与首发验收阶段。本轮不再新增功能，也不再回头做后台、CloudBase 或数据库。目标只有一个：把当前静态作品集正式挂到 GitHub Pages，并完成首发验收准备。请按《docs/统筹/产品统筹-第十三轮GitHubPages正式发布与首发验收指令.txt》推进，并把本轮新增内容、验证结果、剩余问题和需要我决策的事项写回各自交付记录。
