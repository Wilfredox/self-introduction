产品统筹 - 第十四轮 作品下载功能联验与全文件检查指令
更新时间：2026-04-27

一、当前背景

在当前静态作品集主线下，已新增一项真实新需求：

作品展示页面点击一个作品展开后，需要具备：

1. 作品名
2. 简介
3. 图片
4. 下载作品的链接
   - 可能是 Word 文档
   - 可能是 PDF 文件
   - 后续也可能是其他附件

目前主线已完成的状态是：

1. 作品名、简介、图片原本就已存在
2. 本轮已补充：
   - 通用“作品下载文件”能力
   - 首页展开层下载入口
   - 详情页下载入口
   - 静态内容字段支持下载文件配置

因此下一步不再是“要不要做”，而是：

第十四轮：作品下载功能联验与全文件检查

二、本轮目标

本轮只做两类事情：

1. 三方联合验证这次新增的“作品下载文件”功能是否真正闭环
2. 仔细检查当前仓库内所有仍保留的主线文件，确认是否还符合当前静态站要求

本轮不新增其他功能，不恢复后台，不回头做 CloudBase。

三、本轮重点检查对象

这轮新增功能的核心文件，三方都需要知道：

1. `src/pages/WorkDetailPage.tsx`
2. `src/components/ProjectFocusOverlay.tsx`
3. `src/types/content.ts`
4. `src/content/projects.ts`
5. `src/content/placeholders.ts`
6. `src/utils/projectContent.ts`
7. `docs/内容更新说明.md`

四、分工

1. UI 设计

职责：
- 验证新增下载入口在视觉和阅读顺序上是否合理
- 检查展开态和详情页有没有因为新按钮而破坏层级
- 顺手复核公开页文案是否仍然存在明显“说明书语气”

本轮重点检查：
1. 首页展开层里新增下载按钮的位置是否合理
2. 详情页“作品下载”区块是否和现有信息层级协调
3. 下载按钮文案是否足够清楚
4. 新增下载动作是否抢掉“查看在线项目 / 进入详情页”的主次关系

交付要求：
- 更新 `docs/交付/UI设计交付.txt`
- 写清楚：
  1. 下载入口的 UI 判断
  2. 是否建议微调按钮文案或层级
  3. 当前页面是否还能直接对外展示

2. 前端开发

职责：
- 本轮主负责人
- 负责验证新功能是否真正可用
- 负责全文件主线检查

本轮必须完成：
1. 验证首页展开层是否出现下载入口
2. 验证作品详情页是否出现下载入口
3. 验证下载按钮是否带 `download` 行为
4. 验证不同作品是否都能读到：
   - `downloadFileName`
   - `downloadLabel`
   - `downloadText`
5. 重新执行：
   - `npm run build`
6. 检查当前主线文件是否还有：
   - 已删除后端时代残留引用
   - 已无效的旧说明
   - 已不再使用的前端文件

交付要求：
- 更新 `docs/交付/前端交付.txt`
- 写清楚：
  1. 新功能验证结果
  2. build 是否通过
  3. 是否发现主线里还有多余文件或失效引用
  4. 若发现，建议删除或保留原因

3. 后端 / 归档支持

职责：
- 不写后端代码
- 从“数据结构一致性”和“文档真实性”角度验这次新功能
- 帮忙做一次全文件合理性检查

本轮重点检查：
1. 当前类型定义是否已足够表达：
   - 通用下载文件
   - Word / PDF / 其他附件
2. 当前文档是否已经反映：
   - 作品不只是预览 PDF
   - 还可以有独立下载文件
3. 当前 `docs`、`README`、内容维护说明里，是否还有和当前主线冲突的旧表述
4. 当前仓库主线文件中，是否还保留会误导理解的历史材料

交付要求：
- 更新 `docs/交付/后端交付.txt`
- 写清楚：
  1. 当前数据结构是否足够承载这次新需求
  2. 文档是否已同步
  3. 是否还存在会误导协作者的旧文件或旧说明

五、本轮全文件检查范围

三方都需要默认只检查当前主线，不把已删除或归档旧路线重新拉回主线。

当前主线重点检查目录：

1. `src/`
2. `public/`
3. `.github/`
4. `docs/`
5. 根目录：
   - `README.md`
   - `package.json`
   - `package-lock.json`
   - `vite.config.ts`
   - `tsconfig*.json`
   - `index.html`
   - `.gitignore`

检查原则：

1. 文件是否仍被当前主线使用
2. 文件说明是否与当前静态站口径一致
3. 是否存在“已经不再使用，但还留在主线里”的文件
4. 是否存在“已新增功能，但文档未同步”的情况

六、本轮禁止事项

1. 不新增无关功能
2. 不恢复后台
3. 不恢复数据库、CloudBase、上传服务
4. 不把历史旧方案重新带回主线
5. 不因为检查文件而随意删当前主线正在使用的文件

七、本轮完成标准

满足下面 6 条，本轮就算通过：

1. 首页展开层已验证存在作品下载入口
2. 详情页已验证存在作品下载入口
3. 类型与静态内容结构已确认能承载通用下载文件
4. `npm run build` 通过
5. 三方交付记录已更新
6. 三方都完成一轮当前主线文件合理性检查
