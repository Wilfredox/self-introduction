产品统筹 - 第三轮前置修正与职责隔离指令
更新时间：2026-04-26

一、当前项目判断
1. 2.5 轮在“设计补齐”和“前后端口径对齐”方面已经取得实质进展。
2. 但当前项目还不能直接进入第三轮联调与视觉落地。
3. 原因不是需求问题，而是出现了一个协作层面的前置阻塞：
   - 根目录 `index.html` 已被静态设计总览页覆盖
   - 当前前端正式 React 入口没有作为网站正式入口继续生效
   - 当前构建产物输出的是静态设计总览页，而不是正式可联调应用入口

二、当前已确认的事实
1. `src/main.tsx`、`src/app/App.tsx`、路由结构、页面组件仍然存在，说明前端正式应用代码没有丢。
2. 但根目录 `index.html` 当前内容是“A 版设计总览”静态页，不是 Vite + React 的正式挂载入口。
3. 当前 `dist/index.html` 也已经跟随输出为静态设计总览页。
4. 这意味着：
   - 前端工程“能编译”
   - 但当前产物“不是正式网站入口”

三、结论
本项目进入第三轮前，必须先做一次“前置修正”。

这次前置修正不讨论新需求，不讨论视觉方向，也不讨论功能增减。
本轮只做两件事：
1. 恢复正式前端入口
2. 建立文件归属边界，避免设计稿再次覆盖开发入口

四、本轮目标
1. 恢复网站正式入口为 React 应用，而不是静态设计总览页
2. 将设计参考稿和正式开发入口彻底分开
3. 建立设计、前端、后端三方文件归属
4. 为第三轮真实联调、上传接入、后台保存链路、视觉落地创造稳定基础

五、当前阻塞点定义

阻塞点 1：正式入口被静态设计页顶替
当前表现：
- 根目录 `index.html` 为静态设计说明页
- 不存在正式挂载根节点与前端模块入口脚本

这会导致：
1. 打包后用户打开的是“设计总览”，不是网站应用
2. React 路由和页面结构虽然存在，但没有被正式入口使用
3. 后续联调、登录、后台保存、上传功能都没有真正的承载入口

阻塞点 2：设计稿与正式代码仍共享高风险位置
当前表现：
- 设计稿继续放在根目录
- 正式前端入口也依赖根目录

这会导致：
1. 设计补稿容易覆盖前端入口文件
2. 前端继续开发时，也可能误改设计归档页
3. 后续每一轮都会继续出现“构建通过，但构建的是错的东西”

六、本轮冻结结论
1. 首页方向继续冻结为 A 版
2. 设计口径继续以 2.5 轮为准
3. 前后端数据字段继续以 2.5 轮冻结口径为准
4. 本轮不新开页面，不新加功能，不改产品范围
5. 本轮唯一优先级高于一切的目标是：
   - 恢复正式入口
   - 隔离设计稿与开发产物

七、文件归属规则（从本轮开始正式执行）

1. 设计
负责目录：
- 设计参考页目录（需新建独立目录）
- 设计交付记录文件

设计不再直接修改：
- 根目录正式入口文件
- `src/` 下前端代码
- `backend/` 下后端代码

2. 前端
负责目录：
- 根目录正式入口文件
- `src/`
- 前端工程配置文件
- 前端交付记录文件

前端不再负责维护：
- 设计归档页里的静态展示说明内容

3. 后端
负责目录：
- `backend/`
- 后端交付记录文件

后端不参与：
- 根目录设计稿维护
- 前端正式入口结构调整

九、本轮分工

[A] UI / UX 设计
本轮目标：
从正式开发入口撤出，转入独立设计参考区。

本轮必须配合完成：
1. 接受设计稿迁移到独立目录
2. 不再占用根目录 `index.html` 作为设计总览页
3. 设计参考页继续保留：
   - A 版总览
   - 首页 A 稿
   - 作品列表稿
   - 作品详情稿
   - 简历稿
   - 后台稿
4. 后续如需继续补设计说明，只在设计目录内修改

[B] 前端开发
本轮目标：
恢复正式入口，并确认 React 应用重新成为网站正式承载体。

本轮必须完成：
1. 恢复根目录 `index.html` 为正式 Vite + React 入口
   必须具备：
   - `#root` 挂载节点
   - `src/main.tsx` 模块入口
2. 将当前静态设计总览页从根目录移出，不再占用正式入口
3. 确认以下页面仍由 React 路由承载：
   - /
   - /works
   - /works/:slug
   - /resume
   - /admin/login
   - /admin
4. 保持 2.5 轮已完成的数据适配层和容错逻辑不回退
5. 再次验证：
   - `npm run build`
   - 构建产物入口确实为正式应用，不再是静态设计总览页

前端本轮附加建议：
1. 可在 React 应用内增加一个“设计参考入口链接”，但不作为正式首页
2. 若需要保留设计总览页，应该以独立静态页面身份存在，而不是覆盖网站入口

[C] 后端开发
本轮目标：
不参与前端入口争抢，继续为第三轮真实联调做后端准备。

本轮建议推进：
1. 准备本地 PostgreSQL 实跑所需说明
2. 产出并执行 Prisma migration
3. 保持 2.5 轮冻结字段不回退
4. 为第三轮联调准备：
   - 管理员登录
   - bootstrap
   - 作品 CRUD
   - 上传
   - 排序
   - 简历预览

十、本轮验收标准
满足以下条件后，项目才能正式进入第三轮：

1. 正式入口已恢复
- 根目录 `index.html` 不再是静态设计总览页
- 正式入口重新挂载 React 应用

2. 设计稿已隔离
- 设计页已迁移到独立目录
- 后续设计不再直接改正式入口

3. 前端应用仍可正常构建
- `npm run build` 通过
- 构建结果入口为正式网站应用

4. 前端 2.5 轮成果未回退
- A 版首页交互仍在
- 路由仍在
- 数据适配层仍在
- 详情容错仍在

5. 后端继续可编译
- `backend` 仍可正常 build

1. 前端接真实 API
