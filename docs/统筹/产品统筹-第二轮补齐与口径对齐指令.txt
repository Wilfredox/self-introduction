产品统筹 - 第二轮补齐与口径对齐指令（2.5轮）
更新时间：2026-04-26

一、当前项目判断
1. 第二轮不直接视为全部完成。
2. 当前状态是：
   - UI 设计未完成第二轮交付
   - 前端第二轮主体已完成，属于“有条件通过”
   - 后端第二轮主体已完成，属于“有条件通过”
3. 因此本项目先进入“2.5轮”，本轮不是开新需求，而是：
   - 补齐缺失交付
   - 对齐前后端数据口径
   - 冻结第三轮联调前的统一标准

二、本轮目标
本轮只做三件事：
1. 补齐 UI A 版的正式交付
2. 统一前端和后端的数据结构、接口字段和页面所需内容
3. 为第三轮“真实联调 + 视觉落地”扫清阻塞

三、当前事实（已确认）
1. 首页方向仍然只有 A 版：
   横排题头 + 自由拼贴台面
2. 前端项目已正式搭起，且生产构建通过
3. 后端项目已正式搭起，且 TypeScript 编译通过
4. UI 设计记录文件仍停留在第一轮“确认方向”状态，没有进入第二轮高保真与状态说明

四、本轮不变内容
以下内容继续冻结，不在本轮重新讨论：
1. 对外页面
   - 首页
   - 作品列表页
   - 作品详情页
   - 简历页

2. 后台页面
   - /admin/login
   - /admin
   - /admin/profile
   - /admin/projects
   - /admin/resume

3. 不做的功能
   - 分类
   - 搜索
   - 多管理员
   - 注册
   - 推荐/置顶/隐藏机制

4. 首页核心交互不变
   - 顶部横向信息区
   - 拼贴画布
   - 滚轮缩放
   - 拖动画布
   - 点击卡片后在首页内放大简介
   - 放大态第一行展示作品链接

五、本轮要解决的四个阻塞点

1. UI 第二轮缺失
当前缺失的不是“方向”，而是“可开发交付”。
也就是说：
- A 版方向已经选定
- 但没有完成高保真稿、交互状态说明、移动端适配说明、设计标注

2. 首页公开接口命名不一致
当前发现：
- 前端现用结构更接近：
  profile + featuredProjects + resume + contentVersion
- 后端现用结构更接近：
  site + projects + resume + contentVersion

本轮统一决定：
- 公开首页聚合结构以产品统筹文件为准
- 正式字段名冻结为：
  profile + featuredProjects + resume + contentVersion

3. 作品详情字段还没有冻结
当前发现：
- 前端详情页已经实际使用：
  description / role / highlights[] / notes[]
- 后端当前 schema 和公开文档还没有把这组内容正式冻结完

本轮统一决定：
- 作品详情正式字段至少必须支持：
  title
  excerpt
  description
  period
  cover
  pdf
  links[]
  images[]
- 以下字段列为“推荐正式支持”：
  role
  highlights[]
  notes[]

执行原则：
- description 为必备字段
- role / highlights[] / notes[] 可以先按可选字段处理
- 前端在第三轮前不能把这三个字段写成“没有就页面报错”

4. 首页拼贴位置控制暂不进入后台
当前发现：
- 前端首页拼贴位置目前由前端预设槽位控制
- 后端模型尚未支持后台控制每张卡片的位置、尺寸、角度

本轮统一决定：
- 第一版上线范围内，不把拼贴布局编辑能力纳入后台
- 首页拼贴位置先由前端静态控制
- 后续若需要后台控制首页排布，再单独立项

六、本轮统一产品口径

1. 公开首页聚合接口
正式冻结为：

PublicBootstrap
- profile
- featuredProjects
- resume
- contentVersion

其中：

profile
- name
- tagline
- contacts[]

featuredProjects[]
- id
- slug
- title
- excerpt
- period
- status
- sortOrder
- cover
- links[]
- updatedAt

resume
- assetId
- fileName
- url
- previewUrl
- downloadUrl
- updatedAt

说明：
- 首页放大态第一行展示作品链接时，前端直接取 links[] 的第一项作为主链接
- 不额外新增 primaryLink 字段

2. 作品详情页正式字段
作品详情页在第三轮联调前统一按以下结构准备：

ProjectDetail
- id
- slug
- title
- excerpt
- description
- period
- status
- sortOrder
- cover
- pdf
- links[]
- images[]
- role（可选）
- highlights[]（可选）
- notes[]（可选）
- createdAt
- updatedAt

3. 图片与截图说明
截图说明不单独再建新概念：
- 直接使用 images[].caption 作为“截图说明”

4. 简历页
继续冻结为：
- 页面内预览
- 下载按钮

七、2.5轮分工

[A] UI / UX 设计
本轮目标：
补齐第二轮缺失的正式设计交付，不再新增方向讨论。

本轮必须交付：
1. 首页 A 版高保真稿
   - 默认态
   - hover / 聚焦态
   - 首页内放大简介态
2. 作品列表页高保真稿
3. 作品详情页高保真稿
4. 简历页高保真稿
5. 后台登录页高保真稿
6. 后台管理页高保真稿
7. 移动端适配说明
   - 特别说明首页在移动端如何降级或简化交互
8. 设计标注
   - 字号
   - 颜色
   - 间距
   - 卡片规则
   - 关键状态说明

设计注意事项：
1. 首页第一屏里，姓名、一句话介绍、联系方式仍然必须清楚可读
2. 首页放大态里，第一行是作品链接，这一点必须表达清楚
3. 杂志感不能以牺牲招聘浏览效率为代价
4. 不再并行输出 B / C 版

[B] 前端开发
本轮目标：
保持当前结构成果不回退，并完成“接口适配层准备 + 字段容错收口”。

本轮必须交付：
1. 将当前前端所需字段整理成一份明确清单，并记录到前端交付文件
2. 以正式产品口径为准，准备 API 适配层
   - 首页聚合结构改按：
     profile + featuredProjects + resume + contentVersion
3. 首页主链接改由 links[] 第一项派生，不再依赖额外 primaryLink 字段
4. 详情页对以下字段做好容错：
   - role
   - highlights[]
   - notes[]
5. 保持当前页面结构、路由、首页交互不回退
6. 暂不继续深做最终视觉样式，等待 UI 补齐高保真稿后再贴细节

前端注意事项：
1. 本轮不要求全面接真实 API，但必须把“mock 结构”和“正式结构”的差异收口
2. 页面组件不要直接绑死 mock 命名
3. 第三轮联调时，应尽量只替换数据来源，不推翻页面结构

[C] 后端开发
本轮目标：
以产品统筹口径为准，统一公开接口结构，并补足详情字段决议。

本轮必须交付：
1. 更新公开接口结构说明
   - GET /api/public/bootstrap 返回结构改按：
     profile + featuredProjects + resume + contentVersion
2. 更新接口示例文档
   - backend/docs/api-examples.md
3. 补充作品详情字段的正式方案
   至少明确：
   - description 如何存储与返回
   - role / highlights / notes 是否进入正式 schema
4. 若 role / highlights / notes 本轮尚不完整落库，也必须在接口文档中明确：
   - 是否返回空值
   - 字段是否为可选
   - 前端联调时应如何处理
5. 不在本轮把首页拼贴布局位置做成后台可编辑能力

后端建议实现方向：
1. description 建议作为正式必备字段进入项目模型
2. role / highlights / notes 建议作为轻量扩展字段，不要为第一版引入过重内容建模
3. 保持上传、排序、登录三条链路继续可联调

八、跨角色协作规则
1. UI 先补齐 A 版高保真和状态说明
2. 前端、后端先统一字段和接口口径，不继续各自生长
3. 若某字段没有正式冻结，不允许自行在实现里扩散成更多新概念
4. 所有人继续在各自 txt 文件里记录：
   - 本轮新增内容
   - 修改内容
   - 风险点
   - 需要谁配合

九、第三轮准入条件
满足以下条件后，项目才进入第三轮：
1. UI 设计已补齐第二轮正式交付
2. 前端、后端对公开首页聚合字段命名达成一致
3. 作品详情字段已冻结，至少明确必备字段和可选字段
4. backend/docs/api-examples.md 与前端实际准备对接的结构一致
5. 前端和后端都保持当前可编译、可构建状态

十、你发给三个人时可以附上的一句话
“第二轮先不直接转第三轮，先补一个 2.5 轮。请按《产品统筹-第二轮补齐与口径对齐指令.txt》推进，并把本轮新增内容、改动和风险写回各自 txt。”

十一、产品统筹下一步
当三方完成 2.5 轮后，下一次产品统筹重点检查：
1. UI 是否真正达到了可开发交付标准
2. 前后端字段是否已经统一，不再各说各话
3. 第三轮是否可以直接进入：
   - 真实接口联调
   - 上传接入
   - 后台保存链路
   - 视觉细节落地
