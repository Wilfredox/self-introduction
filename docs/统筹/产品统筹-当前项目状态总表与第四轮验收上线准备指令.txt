四、第四轮总目标

第四轮不新增产品范围，只做四件事：
1. 做完整验收
2. 补齐 A 版视觉落地细节
3. 替换真实内容
4. 形成可上线的部署准备清单

五、第四轮分工

[A] UI 设计

本轮角色：
验收审稿 + 视觉收口

本轮必须完成：
1. 对照 design/ 中 A 版稿件，逐页检查正式 React 页面
   - 首页
   - 作品列表页
   - 作品详情页
   - 简历页
   - 后台登录页
   - 后台管理页

2. 重点检查以下视觉点：
   - 首页顶部姓名 / 一句话介绍 / 联系方式的层级是否清楚
   - 首页拼贴卡片的密度、间距、标题换行是否稳定
   - 首页内放大态第一行是否始终先出现作品链接
   - 作品详情页 PDF 预览框是否像“文档容器”而不是普通图片块
   - 简历页是否是“先看，再下载”
   - 后台表单是否清楚、低干扰、易维护

3. 若发现偏差，只做“纠偏意见”，不要新开风格方向

4. 在 `docs/交付/UI设计交付.txt` 中补一段：
   - 第四轮视觉验收结果
   - 哪些页面已通过
   - 哪些页面需前端微调
   - 不通过项的具体位置和原因

UI 本轮验收标准：
1. 明确标记每个页面“通过 / 需微调”
2. 不再新增 B / C 类分支讨论
3. 不改动正式入口和 src/

[B] 前端开发

本轮角色：
浏览器验收执行 + 视觉细节收口 + 上线前前端准备

本轮必须完成：
1. 对照 A 版稿件，逐页完成正式 React 页面视觉收口

2. 完成一轮完整前台验收：
   - 首页加载
   - 首页拖拽 / 缩放
   - 首页点击卡片进入放大简介态
   - 首页放大态第一行展示作品链接
   - 作品列表页非空 / 空态
   - 作品详情页多图、链接、PDF 预览
   - 简历页预览和下载按钮

3. 完成一轮完整后台验收：
   - 登录
   - 读取站点资料
   - 修改姓名 / 一句话介绍 / 联系方式
   - 新增作品
   - 编辑作品
   - 删除作品
   - 上传封面图
   - 上传项目 PDF
   - 上传简历
   - 排序
   - 退出登录

4. 补齐真实前端运行说明
   至少写清楚：
   - 本地开发是否通过 `/api` 代理联调
   - 如果不走代理，`VITE_API_BASE_URL` 应如何设置
   - 正式部署时前端对后端的访问假设是什么

5. 在 `docs/交付/前端交付.txt` 中补一段：
   - 第四轮前台验收结果
   - 第四轮后台验收结果
   - 已完成的视觉收口项
   - 仍存在的问题
   - 本地运行 / 部署前注意事项

前端本轮验收标准：
1. 前台与后台都各有一轮完整手工验收记录
2. 与 A 版设计的主要偏差被列清楚
3. 关键链路没有阻塞性 bug
4. `npm run build` 继续通过

[C] 后端开发

本轮角色：
上线准备收口 + 环境与部署方案明确

本轮必须完成：
1. 整理正式部署前的后端准备清单
   至少写清楚：
   - 正式环境需要哪些环境变量
   - PostgreSQL 如何准备
   - 上传文件正式环境建议如何存储
   - `/api` 反向代理如何配合
   - Cookie 会话在正式域名下的注意点

2. 明确“本地开发环境”和“正式环境”的差异
   - 本地当前用的是什么
   - 正式上线必须换掉什么

3. 如有必要，补一份更明确的后端上线说明
   文件可放在：
   - `backend/README.md`
   - 或 `backend/docs/` 下新文档

4. 补一轮接口和数据状态检查
   重点确认：
   - 发布作品是否允许缺封面
   - 简历预览 URL 是否稳定
   - 上传后的资源 URL 是否适合正式环境
   - 公开接口是否能承接真实作品数据

5. 在 `docs/交付/后端交付.txt` 中补一段：
   - 第四轮后端上线准备结果
   - 正式部署前还缺什么
   - 哪些事项需要你来准备

后端本轮验收标准：
1. 正式部署前需要的后端信息已经说清楚
2. 本地联调口径和正式部署口径区分清楚
3. `npm run build` 继续通过
