产品统筹 - 第四轮技术上线与最终验收指令
更新时间：2026-04-26

一、当前统筹口径

从现在开始，项目先按：
技术上线优先
的路线推进。

说明：
1. 当前不把“真实姓名 / 真实作品 / 真实简历已全部填完”作为本轮阻塞项
2. 本轮目标是先把系统做成：
   - 能部署
   - 能访问
   - 能登录后台
   - 能通过后台修改内容
   - 能支撑后续你自行补真实内容
3. 这意味着当前先追求“技术上可上线、功能上可用”，不等于已经适合立刻公开投递给招聘方

二、两种上线定义

1. 技术上线
指：
- 网站已经能在服务器上跑起来
- 别人能打开
- 前后端链路正常
- 后台可登录
- 作品、简历、站点资料可在后台修改
- 占位内容不会让系统报错

2. 正式公开上线
指：
- 在技术上线的基础上
- 已替换成你的真实姓名、介绍、联系方式、真实作品和真实简历
- 页面内容、视觉细节、文案都适合直接给招聘方看

当前阶段先以：
技术上线
为目标。

三、本轮总目标

第四轮本轮只做 4 件事：
1. 完整验收公开页和后台链路
2. 收口 A 版视觉细节
3. 明确本地 -> 正式环境的部署方式
4. 形成“技术上线通过标准”

四、第四轮分工

[A] UI 设计

本轮角色：
视觉验收与轻量纠偏

本轮必须完成：
1. 对照 design/ 中 A 版稿件，检查正式页面是否存在明显跑偏
2. 重点只看以下页面：
   - 首页
   - 作品列表页
   - 作品详情页
   - 简历页
   - 后台登录页
   - 后台管理页
3. 只输出：
   - 通过项
   - 需微调项
   - 不通过项
4. 不重开新方案，不追加新页面，不改产品范围

UI 本轮输出要求：
在 `docs/交付/UI设计交付.txt` 中补充：
- 第四轮技术上线视觉验收结果
- 每个页面是否通过
- 需要前端微调的点

[B] 前端开发

本轮角色：
公开页与后台页最终验收执行

本轮必须完成：
1. 完成公开页链路验收
   - 首页打开正常
   - 首页可拖拽、可缩放
   - 首页点击卡片后能进入首页内放大简介态
   - 首页放大态第一行是作品链接
   - 作品列表页正常
   - 作品详情页多图 / 外链 / PDF 预览正常
   - 简历页预览与下载正常

2. 完成后台链路验收
   - 登录正常
   - 读取站点资料正常
   - 修改姓名 / 一句话介绍 / 联系方式正常
   - 新增作品正常
   - 编辑作品正常
   - 删除作品正常
   - 上传封面图正常
   - 上传项目 PDF 正常
   - 上传简历正常
   - 排序正常
   - 退出登录正常

3. 完成本地开发与正式部署的前端运行说明
   至少说明：
   - 开发环境是否通过 `/api` 代理
   - 若不走代理，如何配置 `VITE_API_BASE_URL`
   - 正式部署时前端对 `/api` 的假设

4. 若视觉上与 A 版存在明显偏差，优先收口明显问题
   不开新交互，不发散新样式

前端本轮输出要求：
在 `docs/交付/前端交付.txt` 中补充：
- 第四轮公开页验收结果
- 第四轮后台验收结果
- 已处理的视觉收口项
- 未解决问题
- 本地运行与正式部署注意事项

前端本轮通过标准：
1. 能提供完整手工验收结果
2. 前端 build 继续通过
3. 关键公开链路与后台链路无阻塞性 bug

[C] 后端开发

本轮角色：
部署准备与正式环境说明

本轮必须完成：
1. 整理正式环境部署清单
   至少写清楚：
   - 必需环境变量
   - PostgreSQL 如何准备
   - 上传文件正式环境建议存储方式
   - `/api` 如何反向代理到后端
   - Cookie Session 在正式域名下的注意点

2. 明确本地联调环境与正式环境的差异
   当前哪些仅适用于本地
   哪些上线前必须替换

3. 再检查一轮以下后端条件是否适合技术上线：
   - 公开接口能承接占位内容
   - 后台可更新站点资料
   - 后台可更新作品
   - 后台可上传简历
   - 已上传资源 URL 在目标部署形态下可访问

4. 若需要，可在 `backend/docs/` 下补一份更明确的上线说明

后端本轮输出要求：
在 `docs/交付/后端交付.txt` 中补充：
- 第四轮技术上线准备结果
- 正式环境部署要点
- 技术上线前还缺什么
- 需要你后续补什么

后端本轮通过标准：
1. build 继续通过
2. 部署说明已足够让后续上线执行
3. 本地环境与正式环境差异已说明清楚

五、当前不要求的内容

本轮不要求：
1. 不要求你现在就填完真实内容
2. 不要求马上变成最终可投递版本
3. 不要求新增博客、搜索、分类、多管理员
4. 不要求重做首页方向

六、技术上线通过标准

如果以下条件都满足，则判定：
项目达到“技术上线可执行”状态

1. 前端 build 通过
2. 后端 build 通过
3. 公开页主链路可访问
4. 后台主链路可访问
5. 后台改内容后前台能反映
6. 上传链路可用
7. 简历预览 / 下载可用
8. 部署方式清楚
9. 即使当前仍是占位内容，系统也不会因为内容为空或占位而崩溃

七、正式公开上线前仍需补的内容

这一部分不在本轮卡住，但必须记住：
1. 真实姓名
2. 真实一句话介绍
3. 真实联系方式
4. 真实作品
5. 真实简历
6. 最终视觉细节巡检

八、你可以直接发给三个人的话

“项目现在按‘先技术上线，再后台补真实内容’推进。第四轮目标不是扩需求，而是做最终验收和上线准备。请按《docs/统筹/产品统筹-第四轮技术上线与最终验收指令.txt》推进，并把本轮验收结果、部署说明、剩余问题和需要配合的事项写回各自交付记录。”
