产品统筹 - 第三轮问题修复指令
更新时间：2026-04-26

一、当前目标
本轮不是开新功能，而是修复第三轮验收中发现的 3 个具体问题。

本轮只处理：
1. 前端 API 地址回退到 localhost 的问题
2. 后台登录页默认密码写在前端代码里的问题
3. 基本信息页联系方式编辑时直接修改 React state 的问题

二、问题清单

问题 1
文件：
- src/data/realApi.ts

问题：
- 当前 `VITE_API_BASE_URL` 缺失时，会回退到 `http://localhost:4000/api`
- 这会导致网站一旦部署到别人设备上，浏览器去请求“访问者自己的 localhost”
- 结果就是公开页和后台接口都会失效

优先级：
- P1

问题 2
文件：
- src/pages/AdminLoginPage.tsx

问题：
- 登录页当前把密码默认值写在前端代码里
- 这会把演示密码或真实密码暴露进前端 bundle
- 同时也会误导后续联调和上线环境

优先级：
- P2

问题 3
文件：
- src/pages/AdminProfilePage.tsx

问题：
- 当前联系方式列表在 render 中直接 `sort()`，会原地修改 state 数组
- 后续又按 index 写回
- 一旦顺序变化，可能出现编辑错行、删除错行、顺序异常

优先级：
- P2

三、分工

[A] 前端开发
本轮必须完成：

1. 修复 API base 策略
目标：
- 不能再让正式前端在缺少环境变量时自动回退到 `http://localhost:4000/api`

建议实现方向（二选一，优先选第 1 种）：
1. 使用相对路径 `/api`
   - 适合前后端同域部署或反向代理部署
2. 保留 `VITE_API_BASE_URL`，但不再默认写死 localhost
   - 缺失时要明确报错或显式提示环境未配置

要求：
- 正式代码里不能再默默回退到 localhost
- 若保留环境变量方案，需要同步说明开发环境如何配置

2. 去掉后台登录页默认密码
目标：
- 用户名可以保留示例值 `admin`
- 密码输入框默认必须为空
- 不允许在前端源码中保留演示密码或种子密码

3. 修复联系方式编辑状态处理
目标：
- render 时不能直接 `sort()` 原数组
- 应该对副本排序，例如 `[...form.contacts]`
- 更新和删除逻辑应按稳定 `id` 定位，而不是依赖排序后的 index

4. 修改后再次验证
- npm run build
- 检查 dist 产物无报错

前端本轮验收标准：
1. `realApi.ts` 不再内置 localhost 回退
2. `AdminLoginPage.tsx` 默认密码为空
3. `AdminProfilePage.tsx` 不再在 render 中直接改 state 数组
4. 前端 build 通过

[B] 后端开发
本轮配合项：

1. 根据前端修复方向，补一条部署 / 环境约定说明
如果前端改成相对路径 `/api`：
- 后端记录清楚推荐部署方式是同域 / 反向代理

如果前端改成必须使用 `VITE_API_BASE_URL`：
- 后端配合确认本地联调地址和正式部署地址示例

2. 不需要改业务接口结构
除非修复过程中发现接口文档必须补一句说明，否则本轮后端不扩需求、不改字段

后端本轮验收标准：
1. 不改动第三轮已冻结的接口字段
2. 若需要补充说明，只更新后端文档或交付记录

[C] UI 设计
本轮不要求改设计稿

仅需配合确认：
1. 登录页密码输入框默认为空不会影响当前版式
2. 若前端修复联系方式编辑逻辑后出现轻微布局变化，按现有设计口径校对即可

UI 本轮验收标准：
1. 不新增方向
2. 不回退已有设计稿

四、本轮协作规则
1. 只修这 3 个问题，不顺手扩需求
2. 前端先改，后端只做必要说明配合
3. UI 只做校对，不重新起稿
4. 各自继续只改自己负责范围内的文件
5. 每个人完成后，继续更新自己的交付记录
