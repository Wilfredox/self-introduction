产品统筹 - 第二轮正式开工指令
更新时间：2026-04-26

一、当前项目结论
1. 首页 UI 方向已正式选定为 A 方案：
   横排题头 + 自由拼贴台面。
2. 从本轮开始，首页不再并行推进 B、C 方案。
3. 本轮目标从“方案确认”切换为“执行落地”：
   - 统一产品口径
   - 锁定字段和页面状态
   - 进入设计深化、前端搭建、后端建模与接口开发

二、产品目标
这是一个面向招聘方的个人作品展示网站。
核心目标：
1. 让访客快速看到作品
2. 让访客能顺手进入真实项目链接
3. 让访客能在线查看并下载简历
4. 让管理员可以持续新增和维护作品内容

三、已冻结的范围
1. 对外页面
   - 首页
   - 作品列表页
   - 作品详情页
   - 简历页

2. 后台页面
   - /admin 登录页
   - /admin 后台管理页
   - /admin/profile 基本信息维护
   - /admin/projects 作品管理
   - /admin/resume 简历管理

3. 当前不做
   - 分类
   - 搜索
   - 多管理员
   - 注册
   - 推荐/置顶/隐藏机制

四、首页 A 方案的执行定义
1. 顶部横向信息区必须包含：
   - 姓名
   - 一句话介绍
   - 联系方式

2. 首页主体必须为可交互拼贴舞台：
   - 支持滚轮缩放
   - 支持拖动画布
   - 默认卡片显示作品图 + 作品名称

3. 首页卡片点击行为：
   - 不跳离首页
   - 在首页内进入放大简介态
   - 放大态第一行展示作品链接
   - 放大态展示作品简介和进入详情/外链入口

4. 作品列表页：
   - 普通网格布局
   - 不做分类筛选

5. 作品详情页必须支持：
   - 封面
   - 标题
   - 简介
   - 项目时间
   - 多图
   - 截图说明
   - 多个外链
   - PDF 页面内预览

6. 简历页必须支持：
   - 页面内预览
   - 下载按钮

五、统一内容模型
1. SiteProfile
   - name
   - tagline
   - contacts[]
   - resumeAssetId

2. ContactItem
   - id
   - label
   - value
   - href
   - order

3. Project
   - id
   - slug
   - title
   - excerpt
   - period
   - coverAssetId
   - pdfAssetId
   - sortOrder
   - status
   - createdAt
   - updatedAt

4. ProjectLink
   - id
   - label
   - url
   - order

5. ProjectImage
   - id
   - assetId
   - caption
   - order

6. Asset
   - id
   - kind
   - fileName
   - mimeType
   - size
   - url
   - previewUrl

六、统一交互原则
1. 招聘方优先，因此信息结构必须清楚，不能为了“杂志感”牺牲可读性。
2. 首页交互是亮点，但访客必须能快速进入：
   - 作品链接
   - 作品详情
   - 简历下载
3. 前台所有公开内容必须来自后台数据，不允许把正式内容写死在前端代码里。
4. 后台修改成功后，前台应读取到最新内容。
5. 所有上传能力都要优先保证稳定，再考虑视觉包装。

七、第二轮分工

[A] UI / UX 设计
本轮目标：
把 A 方案从“方向原型”深化成“可开发界面稿 + 注释规则”。

本轮必须交付：
1. 首页 A 方案高保真稿
   - 默认浏览态
   - 卡片 hover/聚焦态
   - 卡片点击后的首页内放大简介态
   - 缩放/拖动工具区
2. 作品列表页高保真稿
3. 作品详情页高保真稿
4. 简历页高保真稿
5. 后台登录页高保真稿
6. 后台管理页高保真稿
7. 移动端适配说明
   - 不要求把首页交互完整照搬
   - 但必须说明移动端如何浏览作品、如何进入详情
8. 设计标注
   - 颜色
   - 字号
   - 间距
   - 卡片规则
   - 交互状态说明
9. 内容占位规范
   - 标题最长建议
   - 简介建议长度
   - 联系方式排布建议

设计注意事项：
1. 首页放大态必须把“第一行是作品链接”表现清楚。
2. 顶部姓名、介绍、联系方式不能被拼贴区抢掉信息层级。
3. 后台页面以清晰易用为先，不要做成纯展示稿。

[B] 前端开发
本轮目标：
完成项目脚手架、路由、核心页面骨架、首页交互基础、模拟数据联调层。

本轮必须交付：
1. 正式前端项目初始化
   - React + TypeScript + Vite
   - 路由可访问
2. 页面路由搭建完成
   - /
   - /works
   - /works/:slug
   - /resume
   - /admin/login
   - /admin
   - /admin/profile
   - /admin/projects
   - /admin/resume
3. 首页拼贴舞台基础交互完成
   - 滚轮缩放
   - 拖动画布
   - 点击卡片进入首页内放大简介态
   - 重置视图
4. 页面骨架完成
   - 作品列表页
   - 作品详情页
   - 简历页
   - 后台管理页
5. 前端数据层准备完成
   - types
   - mock data
   - API 封装接口
6. 不允许写死正式内容
   - 可以临时使用 mock 数据
   - 但必须通过统一数据层读取
7. 首页放大态支持通过 URL 保留当前项目状态

前端注意事项：
1. 本轮先保证结构、交互、可替换数据能力。
2. 本轮不要先把视觉细节做死，优先等设计高保真稿。
3. PDF 预览区要预留稳定容器，不要后面再大改结构。

[C] 后端开发
本轮目标：
完成后端项目初始化、数据库结构、认证骨架、公开接口与后台接口的第一版。

本轮必须交付：
1. 正式后端项目初始化
2. 数据库 schema 第一版
   - admin_users
   - admin_sessions
   - site_profiles
   - site_contact_items
   - assets
   - projects
   - project_images
   - project_links
3. 认证能力第一版
   - 单管理员登录
   - 登录态校验
   - 退出登录
4. 公开接口第一版
   - GET /api/public/bootstrap
   - GET /api/public/projects
   - GET /api/public/projects/:slug
   - GET /api/public/resume
5. 后台接口第一版
   - GET/PATCH /api/admin/site
   - GET/POST/PATCH/DELETE /api/admin/projects
   - PUT /api/admin/projects/sort
   - PUT /api/admin/resume
   - 文件上传接口
6. 上传策略第一版
   - 开发环境先走本地 uploads
   - 保留正式环境切对象存储的抽象
7. 接口文档或示例响应
   - 至少给前端明确字段和返回结构

后端注意事项：
1. 简单不等于随便，管理员接口必须受登录保护。
2. 上传接口要校验类型、大小和文件名策略。
3. PDF 预览访问需要考虑稳定 URL 和浏览器兼容。

八、跨角色协作顺序
1. 设计先输出 A 方案高保真和关键状态说明。
2. 前端先用统一 mock 数据搭结构和交互。
3. 后端同步做 schema 和 API。
4. 设计定稿后，前端再把视觉细节贴进去。
5. 前端与后端开始联调公开数据、后台表单、上传、排序、简历预览。

九、第二轮验收标准
1. 产品层面
   - 所有人都按 A 方案推进
   - 字段、页面、接口口径一致

2. 设计层面
   - 不止有静态页面，还包含关键交互状态说明

3. 前端层面
   - 页面可访问
   - 首页交互已跑通
   - 各页面已能由统一 mock 数据渲染

4. 后端层面
   - 接口可被前端对接
   - 登录、作品 CRUD、排序、简历上传这几项路径已经打通或具备明确可测 stub

十、你发给三个人时可以附上的一句话
“首页方向已定为 A 版，现在进入第二轮正式开工。请按这份统一指令推进，并在各自 txt 记录本轮新增内容、风险和需要配合的事项。”

十一、产品统筹下一步
当三方完成第二轮交付后，下一次产品统筹将重点检查：
1. 首页交互是否真正服务招聘浏览
2. 数据字段是否足够支撑长期更新作品
3. 后台是否真的方便单管理员维护
4. 简历上传、预览、下载链路是否顺畅
