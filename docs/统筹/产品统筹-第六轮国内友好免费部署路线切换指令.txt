产品统筹 - 第六轮国内友好免费部署路线切换指令
更新时间：2026-04-26

一、当前路线变更结论

原本第五轮冻结的：
- Render Free Web Service
- Supabase Free

不再作为当前默认路线。

原因：
从“中国大陆用户友好访问”的目标来看，这条路线不再合适作为默认第一版方案。

从现在开始，项目默认路线切换为：
腾讯云开发 CloudBase 国内友好免费路线

二、为什么要切路线

这次不是偏好变化，而是目标变化。

当前新增目标是：
1. 用户主要在中国大陆访问
2. 第一版仍希望尽量免费

在这个前提下：
1. Render 免费服务更偏海外访问链路
2. Supabase 免费方案也更偏海外链路
3. 即使功能能跑，国内用户体验也更容易受：
   - 首次唤醒等待
   - 海外链路延迟
   - 图片 / PDF / 简历资源加载不稳定
影响

因此，当前不再把 Render + Supabase 当作默认交付路线。

三、第六轮冻结的国内友好免费路线

当前统一按下面这条路线推进：

V1 国内友好免费技术上线路线：
1. Tencent CloudBase 免费环境
2. 前端与后台统一迁到 CloudBase 体系
3. 前端优先使用 CloudBase 提供的国内友好托管能力
4. 后端优先迁到 CloudBase HTTP 云函数 / Node 服务承载方式
5. 图片、项目 PDF、简历文件迁到 CloudBase 云存储
6. 数据层优先评估迁到 CloudBase 数据库能力

四、这一轮最重要的统筹提醒

这次路线切换带来的影响很大，必须说清楚：

从 Render + Supabase 切到 CloudBase，
已经不再只是“部署动作变化”，而是：
后端平台适配路线变化

也就是说：
1. 前端影响较小
2. UI 影响最小
3. 后端影响最大

五、当前推荐的最小改造方向

为了减少改动面，本轮先冻结以下实现方向：

1. 前端
- 保持当前 React 前端结构
- 保持公开页与后台页页面结构不推翻
- 优先保留当前页面与组件层

2. 后端服务承载
- 当前 Express 能力优先考虑迁到 CloudBase HTTP 云函数
- 目标是尽量保持现有 API 结构，而不是重写产品接口

3. 文件存储
- 放弃：
  - Render 本地磁盘
  - Supabase Storage
- 改为：
  - CloudBase 云存储

4. 数据存储
- 不再默认按 Supabase Postgres 推进
- 优先由后端评估迁到 CloudBase 数据库能力
- 如果保留 Prisma/Postgres 成本过高，需要明确给出迁移成本与替代方案

六、本轮明确不做的事

第六轮不要做：
1. 不扩新功能
2. 不开新页面
3. 不重做 UI 方向
4. 不继续往 Render + Supabase 上追加工作量
5. 不在没有确认国内路线前继续做“海外平台实配”

七、第六轮分工

[A] UI 设计

本轮角色：
国内友好路线下的视觉与访问复核配合

本轮必须完成：
1. 不新增设计稿
2. 不参与平台技术选型细节
3. 只补一份说明：
   - 哪些页面结构不受平台切换影响
   - 哪些页面上线后需要再看真实图片 / PDF / 简历资源加载效果

4. 在 `docs/交付/UI设计交付.txt` 中补一段：
   - 第六轮国内友好免费路线下的 UI 判断
   - 哪些问题不阻塞国内友好免费技术上线

[B] 前端开发

本轮角色：
前端保持结构稳定，配合后端做平台迁移适配

本轮必须完成：
1. 不推翻当前前端路由与页面结构
2. 明确前端哪些地方依赖后端资源 URL：
   - 图片
   - PDF 预览
   - 简历下载
3. 确认只要后端继续提供稳定的：
   - `url`
   - `previewUrl`
   - `downloadUrl`
前端就可以继续成立

4. 如果后端平台切换后资源字段不变：
   - 本轮前端尽量不新增大改
5. 如果后端平台切换后资源字段变化：
   - 只改适配层，不推翻页面层

6. 在 `docs/交付/前端交付.txt` 中补一段：
   - 第六轮国内友好路线下，前端哪些部分不需要重做
   - 前端真正依赖后端配合的点
   - 国内平台上线后最小前端 smoke check 清单

[C] 后端开发

本轮角色：
平台迁移主负责人

本轮必须完成：
1. 明确从当前路线切到 CloudBase 后，哪些部分：
   - 可以保留
   - 需要重写
   - 需要替换依赖

2. 重点评估以下 4 件事：
   1) Express 如何迁到 CloudBase HTTP 云函数
   2) 当前上传如何迁到 CloudBase 云存储
   3) 当前 Prisma / Postgres 如何处理
   4) 当前管理员登录方案在 CloudBase 下如何保持可用

3. 输出一份清晰迁移结论：
   - 最小改造方案
   - 必改代码点
   - 可以暂缓的点
   - 当前最大技术阻塞

4. 在 `docs/交付/后端交付.txt` 中补一段：
   - 第六轮国内友好免费路线迁移评估结果
   - Render + Supabase 中止后，当前后端最合理的新路线
   - 后端平台迁移的真实工作量判断

后端本轮通过标准：
1. 必须说清楚“这还是部署问题，还是已经变成平台迁移问题”
2. 必须说清楚 Prisma / Postgres 是否继续保留
3. 必须说清楚 CloudBase 下的最小可行技术路线

八、你现在需要知道的真实情况

我要直接讲清楚：

如果改成“国内用户友好 + 免费”路线，
项目不会再是“马上点几下就部署完”的状态了。

因为这意味着：
1. 我们不只是换平台
2. 我们还要重新确认数据库、文件存储、后端承载方式

但这不是坏事。

这只是说明：
当前项目已经从“准备上线”切到了“准备换更合适的上线平台”。
