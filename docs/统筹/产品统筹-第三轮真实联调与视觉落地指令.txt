产品统筹 - 第三轮真实联调与视觉落地指令
更新时间：2026-04-26

一、当前项目结论
1. 第三轮前置修正已完成。
2. 当前已确认：
   - 根目录正式入口已恢复为 React 应用入口
   - 设计参考稿已迁移至 `design/`
   - 前端构建通过，且构建产物入口正确
   - 后端构建通过
   - 前后端 2.5 轮字段口径已基本统一
   - 后端 migration 文件已生成
3. 因此项目现在正式进入第三轮：
   - 真实联调
   - 视觉落地
   - 基础可用性收口

二、第三轮目标
本轮目标不是再确认方向，而是把现有成果真正接成一个能运行、能管理、能演示的网站系统。

第三轮只做四类事情：
1. 前端接真实后端接口
2. 后端接本地 PostgreSQL 并跑通 migration / seed / API
3. 后台关键链路打通
4. 按 A 版高保真稿把 React 页面贴成正式视觉

三、第三轮不变内容
以下内容继续冻结，不在本轮重开讨论：
1. 首页方向仍然只有 A 版
2. 公开页面范围不变：
   - 首页
   - 作品列表页
   - 作品详情页
   - 简历页
3. 后台范围不变：
   - 登录
   - 基本信息维护
   - 作品管理
   - 简历管理
4. 首页拼贴布局位置仍由前端静态控制
5. 不新增：
   - 分类
   - 搜索
   - 多管理员
   - 注册
   - 后台可编辑拼贴布局

四、第三轮联调优先级
第三轮严格按以下顺序推进，不建议跳着做：

1. 后端数据库实跑
2. 公开接口联调
3. 管理员登录联调
4. 后台站点资料联调
5. 作品 CRUD 联调
6. 上传联调
7. 排序联调
8. 简历预览与下载联调
9. React 页面视觉贴合 A 版设计稿
10. 响应式、空态、错误态、保存反馈收口

五、统一接口口径（继续冻结）

1. 公开首页聚合结构
PublicBootstrap
- profile
- featuredProjects
- resume
- contentVersion

2. 作品详情结构
ProjectDetail
- id
- slug
- title
- excerpt
- description
- period
- status
- sortOrder
- cover
- pdf
- links[]
- images[]
- role（可选）
- highlights[]（可选）
- notes[]（可选）
- createdAt
- updatedAt

3. 首页主链接
- 一律取 `links[]` 第一项
- 不额外恢复 `primaryLink`

4. 截图说明
- 继续使用 `images[].caption`

六、第三轮分工

[A] UI / UX 设计
本轮角色：
从“补稿”切换为“落地审稿与视觉纠偏”。

本轮主要任务：
1. 以 `design/` 中 A 版稿件为唯一视觉基线
2. 配合前端做 React 页面视觉贴合
3. 核对以下重点是否落地一致：
   - 首页顶部信息层级
   - 拼贴区卡片默认态 / hover / 聚焦态
   - 首页内放大简介态
   - 作品列表页网格密度
   - 详情页主次信息区
   - 简历页预览与下载关系
   - 后台页安静、清楚、低干扰的基调
4. 补充第三轮中发现的细节规则：
   - 文本超长时如何收束
   - 移动端降级后的间距与层级
   - PDF 预览容器视觉边界

本轮不再做：
1. 重新提新首页方向
2. 把设计稿重新占用正式入口
3. 临时扩展新功能

[B] 前端开发
本轮角色：
从 mock 驱动切换到真实接口驱动，并完成视觉落地。

本轮必须完成：
1. 将公开页从 mock API 切到真实 API
   - GET /api/public/bootstrap
   - GET /api/public/projects
   - GET /api/public/projects/:slug
   - GET /api/public/resume

2. 将后台登录与后台页切到真实 API
   - POST /api/admin/auth/login
   - GET /api/admin/auth/me
   - POST /api/admin/auth/logout
   - GET /api/admin/site
   - PATCH /api/admin/site
   - GET /api/admin/projects
   - POST /api/admin/projects
   - GET /api/admin/projects/:id
   - PATCH /api/admin/projects/:id
   - DELETE /api/admin/projects/:id
   - PUT /api/admin/projects/sort
   - PUT /api/admin/resume
   - 上传接口

3. 处理后台请求携带 Cookie Session
   - 请求需带 credentials
   - 不按 JWT 方案自行扩写

4. 接入真实上传链路
   - 封面图上传
   - 项目多图上传
   - PDF 上传
   - 简历上传

5. 接入真实排序保存链路
   - 提交 `projectIds` 顺序数组

6. 保持当前推荐字段容错逻辑
   - role 可缺失
   - highlights 可为空
   - notes 可为空

7. 按 A 版高保真稿完成正式视觉贴合
   - 重点优先公开页
   - 后台页以清楚易用为先

8. 补齐关键交互反馈
   - loading
   - empty
   - error
   - save success / fail
   - unauthorized

前端本轮注意事项：
1. 接真实 API 时优先替换 transport 和 query 层，不推翻页面结构
2. 不要把 design/ 下静态稿重新搬回正式入口
3. 联调中如发现字段缺口，先记录到 `前端交付.txt`，不要自行发散新字段

[C] 后端开发
本轮角色：
把“能编译的后端”推进成“能被前端真实调用的后端”。

本轮必须完成：
1. 准备本地 PostgreSQL
2. 配置 `.env`
3. 执行：
   - `npm run prisma:generate`
   - `npm run prisma:migrate:deploy`
   - `npm run prisma:seed`
4. 启动后端服务并验证：
   - `GET /api/health`
   - `GET /api/public/bootstrap`
   - `GET /api/public/projects`
5. 配合前端联调以下链路：
   - 登录
   - 获取登录态
   - 站点资料更新
   - 作品新增 / 编辑 / 删除
   - 上传
   - 排序
   - 简历替换与预览

6. 保持第三轮字段口径不回退
   - `description` 必填
   - `role` 可为空
   - `highlights` / `notes` 为空数组安全返回

7. 若联调中发现返回结构与文档不一致
   - 先修正文档或实现
   - 不允许“文档一套、接口一套、前端再猜一套”

后端本轮注意事项：
1. 公开接口与后台接口都要以真实可调用为目标，不再停留在骨架层
2. 上传后返回的 URL、previewUrl、downloadUrl 要稳定
3. PDF 预览要确保浏览器可访问

七、第三轮建议联调节奏

阶段 1：环境跑通
1. 后端跑 PostgreSQL + migrate + seed
2. 前端确认本地可访问正式入口
3. 双方确认基础 URL、端口、CORS、Cookie 策略

阶段 2：公开页联调
1. 首页 bootstrap
2. 作品列表
3. 作品详情
4. 简历预览 / 下载

阶段 3：后台联调
1. 登录 / 退出 / 登录态
2. 基本资料更新
3. 作品 CRUD
4. 上传
5. 排序
6. 简历替换

阶段 4：视觉贴合与收口
1. 首页贴 A 版高保真
2. 列表、详情、简历页贴视觉
3. 后台页面整理
4. 移动端降级和细节收口

八、第三轮验收标准
满足以下条件，第三轮才算通过：

1. 公开访问链路可用
- 首页能加载真实数据
- 作品列表能加载真实数据
- 作品详情能加载真实数据
- 简历能预览与下载

2. 后台链路可用
- 管理员能登录
- 能修改站点基本信息
- 能新增作品
- 能编辑作品
- 能删除作品
- 能上传封面 / 多图 / PDF / 简历
- 能排序作品

3. 前端视觉落地可用
- 首页整体贴近 A 版高保真
- 详情页结构清楚
- 简历页清楚
- 后台页可用

4. 基础状态可用
- loading / empty / error 有基本处理
- 保存成功 / 失败有反馈
- 未登录访问后台有处理

5. 技术状态可用
- 前端 build 通过
- 后端 build 通过
- 数据库 migration 可执行
