二、A 方案定义
方案名称：横排题头 + 自由拼贴台面

核心特征：
1. 顶部信息采用横向排版：
   - 左侧放姓名
   - 中间放一句话介绍
   - 右侧放联系方式
2. 首页主体为自由拼贴感作品展示区，强调“作品集封面感”。
3. 画布支持拖动与滚轮缩放，访客可以像浏览展板一样查看作品。
4. 作品卡片默认展示作品图和名称。
5. 点击作品卡后，不跳离首页，而是在首页内放大展开作品简介。
6. 放大后的简介画面第一行放作品链接，保证招聘方能快速进入真实项目。

四、与 A 方案相关的设计判断
1. A 方案更强调第一眼的视觉记忆点，适合把首页作为作品集封面来处理。
2. 该方案在招聘场景下的优势是：
   - 姓名、介绍、联系方式首屏可见
   - 作品区更有辨识度
   - 点击后仍留在首页内，浏览路径连贯
3. 后续如果继续深化，将以 A 方案为唯一首页方向，不再并行推进 B、C 方案。

  - 那数据库部分就属于本轮最大的后端迁移项，而不是 UI 侧可忽略的小改动。

  - 后端如果仍把临时访问 URL 当成数据库里的长期正式 URL
  - 则历史图片、项目 PDF、简历 PDF 未来可能失效
- 因此 UI 最终验收仍依赖：
  - 后端完成“持久化 fileID / objectKey，读时生成当前可访问 URL”
  - 前端完成最小 smoke check 并确认展示链路未被打散

4. 需要我决策的事项
- UI 侧本轮暂无新增设计决策项。
- 等 CloudBase 实际可访问环境和修复后的资源链路准备好后，只需要进入一次最终视觉复核即可。

5. 结论
- 第八轮 UI 无新增设计改动，继续保持 A 版首页与全站页面结构不变。
- 当前上线封板对 UI 的核心要求已经收束为一句话：
  - 资源要正常显示，页面不要被打散
- 等后端完成资产 URL 修复、前端完成 smoke check 后，UI 再做最后一轮图片 / PDF / 简历预览复核。
