工作区文件归属与协作规则
更新时间：2026-04-26

一、当前工作区结构

1. 前端正式应用
- index.html
- package.json
- package-lock.json
- vite.config.ts
- vite.config.js
- vite.config.d.ts
- tsconfig.json
- tsconfig.app.json
- tsconfig.node.json
- src/
- public/

2. 后端正式应用
- backend/

3. 设计参考稿
- design/

4. 项目统筹与记录
- docs/统筹/
- docs/交付/

5. 构建或运行产物（只读，不手改）
- dist/
- node_modules/
- backend/dist/
- backend/node_modules/
- *.tsbuildinfo
- vite-dev.log
- vite-dev-error.log

二、每个人的工作范围

[1] UI 设计
只允许修改：
- design/**
- docs/交付/UI设计交付.txt

只允许查看，不允许直接修改：
- index.html
- src/**
- public/**
- backend/**
- docs/统筹/**

UI 设计的职责：
1. 维护 A 版及其他归档设计稿
2. 维护设计说明、状态说明、移动端说明
3. 给前端提供视觉基线，不直接改正式 React 页面代码

[2] 前端开发
只允许修改：
- index.html
- package.json
- package-lock.json
- vite.config.ts
- vite.config.js
- vite.config.d.ts
- tsconfig.json
- tsconfig.app.json
- tsconfig.node.json
- src/**
- public/**
- docs/交付/前端交付.txt

只允许查看，不允许直接修改：
- design/**
- backend/**
- docs/统筹/**

前端开发的职责：
1. 维护正式网站入口
2. 维护公开页和后台页 React 代码
3. 接后端真实接口
4. 落地 UI A 版视觉

[3] 后端开发
只允许修改：
- backend/**
- docs/交付/后端交付.txt

只允许查看，不允许直接修改：
- index.html
- src/**
- public/**
- design/**
- docs/统筹/**

后端开发的职责：
1. 维护 API、数据库、上传、登录、排序、简历链路
2. 维护 Prisma schema、migration、seed、接口文档
3. 保持与前端联调口径一致

[4] 产品 / 项目统筹
只允许修改：
- docs/统筹/**
- 工作区-文件归属与协作规则.txt

产品统筹的职责：
1. 发阶段指令
2. 定冻结范围和优先级
3. 做验收判断
4. 协调 UI、前端、后端的边界和节奏

三、绝对不要手改的内容

以下内容任何人都不要手改：
1. dist/**
2. node_modules/**
3. backend/dist/**
4. backend/node_modules/**
5. *.tsbuildinfo
6. vite-dev.log
7. vite-dev-error.log

说明：
这些是构建产物、依赖目录或运行缓存。
如果它们需要变化，应通过：
- npm install
- npm run build
- npm run dev
- backend 相关脚本
自动生成。

四、协作规则

1. 改文件前先报备
统一格式：
“我现在要修改：xxx”

2. 不跨范围修改
如果需要别人配合，只在自己的交付记录里写清楚，不直接改对方负责区。

3. 每轮结束必须更新自己的记录文件
- UI：docs/交付/UI设计交付.txt
- 前端：docs/交付/前端交付.txt
- 后端：docs/交付/后端交付.txt

4. 记录里必须写明
1. 本轮做了什么
2. 修改了哪些文件
3. 当前风险
4. 需要谁配合

五、当前建议查看顺序

新进入项目的人，建议先看：
1. docs/统筹/产品统筹-第三轮真实联调与视觉落地指令.txt
2. 工作区-文件归属与协作规则.txt
3. docs/交付/UI设计交付.txt
4. docs/交付/前端交付.txt
5. docs/交付/后端交付.txt

六、当前目录口径

1. design/ 是设计参考区，不是正式网站入口
2. index.html + src/ 是正式前端应用入口
3. backend/ 是正式后端应用目录
4. docs/统筹/ 存放产品统筹指令
5. docs/交付/ 存放三方记录文件

七、当前阶段一句话说明

现在所有人都在同一个总文件夹工作，但不是谁都能碰所有文件。
后续按“设计看 design、前端看 src、后端看 backend、统筹看 docs/统筹”的方式协作。
